# 变量、基本类型与整数溢出处理

> 进度状态只能是 `not-started`、`learning`、`practiced`、`mastered` 之一，与 `学习管理/学习进度.md` 保持一致。当前状态：`learning`（第七段练习阶梯尚未开始）。
> 本笔记中所有数值断言均已在 rustc 1.92.0 上实测（debug 与 `-O` 两种构建），实测记录见第 4.2 节。

## 1. 引入问题

**题目**：输入一行两个整数 `a`、`b`，满足 −10⁹ ≤ `a`, `b` ≤ 10⁹，输出 `a × b` 的精确值。

```
输入：1000000000 1000000000
输出：1000000000000000000
```

**直觉做法**：

```rust
let a = ...;      // 不写类型标注，默认 i32
let b = ...;
let c = a * b;
println!("{}", c);
```

**瓶颈**：正确答案 10¹⁸，而 `i32` 上限是 2 147 483 647（约 2.1×10⁹），差了 4.7 亿倍。并且 Rust **不会自动升宽**：`i32 * i32` 的结果类型仍然是 `i32`，溢出就溢出。

**一条被否决的替代方案**：首次作答时提出的「固定 `a`、逐位拆 `b` 的数字、乘 `10^(len-i-1)` 累加进数组」是**高精度大数乘法**。方向正确，但对本题是杀鸡用牛刀：结果 10¹⁸ 仍在 `i64` 内（上限 9.22×10¹⁸）。高精度只在结果超过 `i128` 上限（约 1.7×10³⁸）时才必需，见第七段第 5 题。

## 2. 手算直觉

### 2.1 4 位玩具模型

把位宽砍到 4 位（记作 i4），原理与 `i32` 完全一致。4 位二进制共 16 个格子，按补码读：

| 二进制 | 值 | 二进制 | 值 |
|---|---|---|---|
| `0000` | 0 | `1000` | −8 |
| `0001` | 1 | `1001` | −7 |
| `0010` | 2 | `1010` | −6 |
| `0011` | 3 | `1011` | −5 |
| `0100` | 4 | `1100` | −4 |
| `0101` | 5 | `1101` | −3 |
| `0110` | 6 | `1110` | −2 |
| `0111` | 7 | `1111` | −1 |

范围是 −8 ~ 7，共 16 个值。

### 2.2 推演 3 × 5

| 步 | 状态 |
|---|---|
| 1 | 真值 3 × 5 = **15** |
| 2 | 15 的 4 位表示 `1111` |
| 3 | 按有符号读 `1111` → **−1** |

所以 4 位整数里 **3 × 5 = −1**。

### 2.3 推演 6 × 3

| 步 | 状态 |
|---|---|
| 1 | 真值 6 × 3 = **18** |
| 2 | 18 需要 5 位：`10010` |
| 3 | 只保留低 4 位 → `0010` |
| 4 | 按有符号读 → **2** |

### 2.4 可复用的两步法

> **写回**：真值 T → 取 T mod 2^w 的**非负余数** → 得到低 w 位。
> **读回**：无符号值 U = 各位置权值相加；若最高位为 1（U ≥ 2^(w−1)），有符号值 = U − 2^w，否则 = U。

验证：−21 → −21 mod 16 = 11 → `1011` → 11 ≥ 8 → 11 − 16 = **−5**。真实位宽同理：`i8` 里 100 × 2 = 200 → `1100_1000` → 无符号 200 ≥ 128 → 200 − 256 = **−56**。

## 3. 形式化思想

### 3.1 取值范围与编码

w 位有符号整数（补码）的范围是 [−2^(w−1), 2^(w−1) − 1]：

| 类型     | 位宽  | 范围                                         |
| ------ | --- | ------------------------------------------ |
| `i8`   | 8   | −128 ~ 127                                 |
| `i32`  | 32  | −2 147 483 648 ~ 2 147 483 647（约 ±2.1×10⁹） |
| `i64`  | 64  | 约 ±9.22×10¹⁸                               |
| `i128` | 128 | 约 ±1.7×10³⁸                                |
| `u64`  | 64  | 0 ~ 约 1.8×10¹⁹                             |

### 3.2 溢出与回绕

> 当 `a op b` 的数学真值超出该类型的取值范围时，发生**溢出**（overflow）。
> 硬件只保留低 w 位，结果 = 真值 mod 2^w 重新读成有符号，这称为**回绕**（wrap around）。

回绕的后果是**确定的**（补码的加减乘在模 2^w 意义下自洽），但**不正确**。注意回绕不是「丢弃高位」，而是「保住低位并重新定符号」——这正是 `3 × 5` 变成 `−1` 而非 `7` 的原因。

### 3.3 三种情形下的行为（实测，rustc 1.92.0）

| 情形 | 实测行为 |
|---|---|
| 编译期可求值的常量溢出 | **编译错误**：`error: this arithmetic operation will overflow`，附带 `#[deny(arithmetic_overflow)]` |
| 运行期数值 + debug 构建（`rustc` 不带 `-O`、`cargo run`、`cargo test`） | 运行时 **panic**：`attempt to multiply with overflow`，退出码 1 |
| 运行期数值 + `-O` / release 构建（OJ 判题常见） | **静默回绕**，输出错误值，无任何报错 |

实测记录（输入 100000，求 `n * n`，n 为 `i32`）：

- debug：`thread 'main' panicked at rt.rs:7:20: attempt to multiply with overflow`，退出码 1
- release：`1410065408`（= 10¹⁰ mod 2³²）

**铁律**：不要依赖编译器的溢出检查来判断正确性。OJ 以优化构建判题，调试期的 panic 在提交后会变成静默错值。语义必须在代码里显式选择。

### 3.4 显式语义六件套

设 `a`、`b` 同类型（`mul` 可换 `add`、`sub`、`div`）：

| 写法 | 溢出行为 | 返回类型 | 竞赛用途 |
|---|---|---|---|
| `a * b` | 常量→编译错误；运行期 debug panic / release 回绕 | `T` | 已确认不溢出时的默认写法 |
| `a.wrapping_mul(b)` | 回绕（= mod 2^w） | `T` | 需要自然溢出：哈希、对 2^64 取模 |
| `a.checked_mul(b)` | 返回 `None` | `Option<T>` | 判断溢出并分支处理 |
| `a.overflowing_mul(b)` | 回绕 + 溢出标志 | `(T, bool)` | 既要值又要标志 |
| `a.saturating_mul(b)` | 卡在类型边界 | `T` | 极少用于答案 |
| `Wrapping<T>` | 整类运算回绕 | `Wrapping<T>` | 大量回绕运算时代替到处写 `_` |

外加一条**最常用的「隐藏技能」**：先升宽再运算，`(a as i64) * (b as i64)`。竞赛里 90% 的溢出问题靠这一条解决，而非 `wrapping_*` 或 `checked_*`。

### 3.5 位宽选择阶梯

判断标准不是「输入多大」，而是「**结果最大能多大**」：

| 结果上界 | 最小够用类型 |
|---|---|
| ≤ 2.1×10⁹ | `i32` |
| ≤ 9.2×10¹⁸ | `i64`（竞赛默认） |
| ≤ 1.8×10¹⁹（非负） | `u64` |
| ≤ 1.7×10³⁸ | `i128` / `u128` |
| 更大 | 高精度（手写数组 / 十进制串） |

乘法要**先估位数**：10^a × 10^b = 10^(a+b)。

### 3.6 不变量与正确性理由

> **不变量**：只要每一步的真值都落在 [−2^(w−1), 2^(w−1) − 1] 内，位模式与真值一一对应，运算结果精确无误。

因此风险评估只需回答一句：**「我的中间量最大可能值是多少？在范围内吗？」** 是 → 用裸运算；否 → 升宽、取模乘法或高精度。

## 4. Rust 实现

### 4.1 引入题的完整解

```rust
use std::io::{self, Read};

fn main() {
    // ① 把整个标准输入读进一个堆上的 String
    let mut input = String::new();
    io::stdin().read_to_string(&mut input).unwrap();

    // ② 切成「词」，惰性解析成 i64
    let mut nums = input.split_whitespace().map(|s| s.parse::<i64>().unwrap());

    let a = nums.next().unwrap();
    let b = nums.next().unwrap();

    // ③ 在 i64 上相乘：最大 10^9 × 10^9 = 10^18 < 9.22 × 10^18，安全
    println!("{}", a * b);
}
```

逐段解释与对应的 Rust 语言特性：

| 代码 | 作用 | 语言特性 |
|---|---|---|
| `let mut input = String::new();` | 堆上可增长字符串 | `String` 拥有所有权（owned）；`mut` 允许修改 |
| `read_to_string(&mut input)` | 一次性读完 stdin | **可变借用** `&mut`：写权限临时借给函数，所有权仍在 `main` |
| `.unwrap()` | 取 `Result` 的成功值，失败则 panic | `Result<T, E>` |
| `split_whitespace()` | 按空白切分，返回迭代器 | 迭代器**惰性**；产出的 `&str` **借用自 `input`** |
| `.map(\|s\| s.parse::<i64>()...)` | 逐段解析 | `parse` 返回 `Result`；`::<i64>` 是涡轮鱼语法 |
| `let mut nums = ...` | 绑定迭代器 | 需要 `mut`，因为 `next()` 会推进内部游标 |
| `a * b` | i64 乘法 | 两个 `i64` 相乘结果仍是 `i64`，不会自动升宽 |

三个必须记住的点：

1. **Rust 不会自动升宽**，必须显式 `as i64`。
2. **`&mut input` 是借用不是移动**；写成 `input`（去掉 `&mut`）会类型不匹配编译失败。可变借用期间外部连读都不允许（独占借用）。
3. **读入用 `read_to_string` 一次读完**，比循环 `read_line` 更快也更好写。

### 4.2 六件套实测输出

```rust
use std::num::Wrapping;

fn main() {
    let (a, b) = (1_000_000_000i32, 1_000_000_000i32);

    // ① 裸运算 a * b 在此不能用：常量表达式直接编译错误，运行期值则 debug panic
    println!("wrapping   : {}", a.wrapping_mul(b));
    println!("checked    : {:?}", a.checked_mul(b));

    let (v, of) = a.overflowing_mul(b);
    println!("overflowing: ({}, {})", v, of);

    println!("saturating : {}", a.saturating_mul(b));
    println!("Wrapping   : {}", (Wrapping(a) * Wrapping(b)).0);
}
```

rustc 1.92.0 实测输出：

```
wrapping   : -1486618624
checked    : None
overflowing: (-1486618624, true)
saturating : 2147483647
Wrapping   : -1486618624
```

`-1486618624` 的来历：10¹⁸ mod 2³² = 2 808 348 672，且 2 808 348 672 ≥ 2³¹，所以读成有符号是 2 808 348 672 − 4 294 967 296 = −1 486 618 624。正是第 2 段那套两步法。

### 4.3 哈希场景：`wrapping_*` 与 `Wrapping<T>`

目标：字符串滚动哈希，对 2⁶⁴ 取模。两个等价版本（实测 `hash_str("hello")` 均为 `30856916622`）：

```rust
// 版本 A：直接写 wrapping_*
fn hash_str(s: &str) -> u64 {
    let mut h: u64 = 0;
    for &c in s.as_bytes() {
        h = h.wrapping_mul(131).wrapping_add(c as u64);
    }
    h
}

// 版本 B：Wrapping<u64>，运算符自动回绕
fn hash_str2(s: &str) -> u64 {
    use std::num::Wrapping;
    let mut h = Wrapping(0u64);
    for &c in s.as_bytes() {
        h = h * Wrapping(131) + Wrapping(c as u64);
    }
    h.0
}
```

关键认知：`u64` 上的 `wrapping_mul` **就是**对 2⁶⁴ 取模，代码里不需要写 `% (1u64 << 64)`——位宽本身提供了这个模。

### 4.4 `checked_*` 的分支写法

```rust
fn solve(x: u32, y: u32) -> String {
    match x.checked_add(y) {
        Some(sum) => sum.to_string(),
        None => "-1".to_string(),
    }
}
```

注意：`checked_add` 判断的是**类型溢出**，不是业务阈值。若题目要求「和超过 10⁹ 输出 −1」，那要自己比大小，`checked_*` 管不着。

## 5. 复杂度

| 操作 | 复杂度 | 说明 |
|---|---|---|
| `read_to_string` | O(D) | D = 输入字符数 |
| `i64` 乘法 | O(1) | 位宽固定，一条硬件指令 |
| `i128` 乘法 | O(1)，常数更大 | 无 128 位乘法指令，编译为 2~4 条 64 位乘法拼装 |
| 高精度乘法（十进制数组） | O(L²) | L = 位数，朴素双重循环 |

- **时间复杂度**：整体 O(D)，运算部分 O(1)。
- **空间复杂度**：`read_to_string` 为 O(D)；流式解析可降到 O(1)。
- **适用数据范围**：结果 ≤ 9.2×10¹⁸ 用 `i64` 单指令即可，任何 OJ 上都是 0 ms；结果 ≤ 1.7×10³⁸ 用 `i128`，但若在 10⁷ 次循环内，`i128` 比 `i64` 慢 2~5 倍，应优先考虑取模乘法；更大只能高精度。

数据范围自检公式：

> 写 `a op b` 前先算上界。加法取 |a| + |b|，乘法取 |a| × |b|（位数相加）。

实测校核：20! = 2 432 902 008 176 640 000 在 `i64` 内；21! ≈ 5.11×10¹⁹ 超出；10¹⁰ × 10¹⁰ = 10²⁰ 需要 `u128`。

## 6. 三个易错点

### 6.1 不写类型标注 → 默认掉进 `i32`

**反例**（必须用**运行期数值**才能复现，常量会被编译器直接拦下）：

```rust
use std::io::{self, Read};

fn main() {
    let mut s = String::new();
    io::stdin().read_to_string(&mut s).unwrap();
    let n: i32 = s.trim().parse().unwrap();   // 输入 100000
    println!("{}", n * n);
}
```

- debug 构建：panic `attempt to multiply with overflow`，退出码 1
- release 构建：静默输出 **1410065408**（= 10¹⁰ mod 2³²）

补充：若写成 `let n = 100_000; let n2 = n * n;`，编译器在**编译期**即报 `arithmetic_overflow` 错误——错误暴露得更早，但也说明复现「debug panic」必须用运行期数值。

**防再犯检查项**：参与乘法的变量在声明处显式写 `i64`（或读入后立刻 `as i64`）；看到无类型标注的 `let x = 数字;` 就警觉。

### 6.2 最终答案合法，但中间量溢出

**反例 A（求平均）**：

```rust
let (a, b) = (2_000_000_000i32, 2_000_000_000i32);
println!("{}", (a + b) / 2);   // 期望 2000000000，实测 -147483648
```

`a + b` 先回绕成 −294 967 296，再除 2。修法：`(a as i64 + b as i64) / 2`（实测 2000000000）。

**反例 B（取模乘法）**：

```rust
const MOD: i32 = 1_000_000_007;
let (a, b) = (1_000_000_000i32, 1_000_000_000i32);
println!("{}", a * b % MOD);   // 实测 -486618617（负数）
```

乘积先溢出成 −1 486 618 624，再取模带出负号。正确值应为 **49**（因为 10¹⁸ = (10⁹+7)(10⁹−7) + 49），修法 `a as i64 * b as i64 % MOD as i64`。

**防再犯检查项**：写任何 `+ − *` 之前写出该表达式的最大可能绝对值，超过 2.1×10⁹（`i32`）或 9.2×10¹⁸（`i64`）就地升宽。

### 6.3 `%` 是余数，不是非负取模

**反例**：

```rust
println!("{}", -21i32 % 16);            // -5  ← 余数，符号跟随被除数
println!("{}", (-21i32).rem_euclid(16)); // 11  ← 非负取模
```

−21 的低 4 位是 `1011` = **11**，而 `%` 给出 **−5**。拿它当数组下标直接 panic，拿来算哈希会得到负值。

**防再犯检查项**：表达式里出现 `%` 且被除数可能为负 → 改 `rem_euclid` 或 `((x % m) + m) % m`。

fn main() {
